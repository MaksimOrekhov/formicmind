# Ecosystem v1 — E1-a: исполняемый генератор карты (FOR-44)

Статус: **реализовано** (код `src/formicmind/eco/`, тесты `tests/test_eco_*.py`). Это первый исполняемый шаг плана
[миграции](ecosystem_v1_migration.md) (PR-0 + PR-1 в одном PR по указанию FOR-44). Здесь **нет** движения, добычи, экономического цикла,
боя, наград и обучения: только независимые схемы мира, детерминированный генератор общей карты 6–8 колоний, проверка справедливости и CLI.
Проектные документы ([видение](ecosystem_v1_vision.md), [RFC](ecosystem_v1_rfc.md), [контракты](ecosystem_v1_contracts.md),
[экономика](ecosystem_v1_economy.md)) не менялись.

Метки: **[L0]** — факт L0; **[E1]** — реализованное правило E1; **[ОТКЛОНЕНИЕ]** — реализация уточняет или отличается от текста контрактов (список в §5).

## 1. Быстрый старт (Windows, Python ≥ 3.12, без сторонних пакетов)

```bash
python -m formicmind.eco map --seed 42 --colonies 8 --scenario moderate --report --state --summary --out map.json
python -m formicmind.eco verify map.json                      # строгая схема, хэши, перегенерация из seed, пересчёт отчёта
python -m formicmind.eco bench --maps 100 --colonies 8        # латентность генерации (НЕ миров в секунду: симуляции нет)
python -m formicmind.eco sweep --maps 200                     # справедливость на 200 картах × 3 размера × 3 сценария
```

Вывод `map` — стабильный JSON (отсортированные ключи, только `int/str/bool/list/dict`, u64 — десятичные строки, LF). Поля верхнего уровня:
`schema`, `versions`, `map_seed`, `config`, `config_hash`, `map`, `map_hash`, [`report`, `report_hash`], [`initial_state`], `document_sha256`.
В нём нет наблюдений, масок, действий, наград и вообще данных политики: это **вид движка/viewer** (полная карта).

Воспроизводимые артефакты в репозитории: [docs/ecosystem_examples/](ecosystem_examples/)

| Файл | Что это | Как воспроизвести |

| `map_seed42_moderate_8.json` | карта 8 колоний, 96 узлов, 32 площадки, отчёт справедливости и сводка состояния тика 0 | `python -m formicmind.eco map --seed 42 --colonies 8 --scenario moderate --report --state --out …` (тест `test_the_committed_example_is_what_the_cli_produces_today` сравнивает побайтно) |

## 3. Алгоритм `eco-mapgen-v1` (одна RNG-поток `map`, только целые числа)

1. **Гнёзда.** Best-candidate в центральном квадрате, затем целочисленная релаксация отталкиванием до расстояния ≈ `min_nest_path − 1` тиков: нерегулярно, без зеркальности.
2. **Узлы.** Несколько обычных перекрёстков вокруг каждого гнезда (2.2–4.8 тика), по одному там, где встречаются соседи (середины пар по Габриэлю, центры описанных окружностей треугольников Делоне),
   затем dart throwing до `n_nodes` (по умолчанию `8·N + 32`: 80 / 88 / 96). Метки роли узлы не получают.
3. **Рёбра.** Евклидово MST (связно, без пересечений) + рёбра к `edge_k = 3` ближайшим соседям без пересечений (степень ≤ 5); гнёздам гарантированы ≥ 2 ребра. Длина `= clamp(ceil(dist/24), 2, 6)` тиков.
4. **Роли по длине пути, а не по геометрии.** От каждого гнезда считается кратчайший путь по готовому графу; затем: `near` — перекрёсток в 3–5 тиках от одного гнезда и ≥ 4 тиков ближе к нему, чем к любому другому;
   `border` — перекрёсток с двумя близкими соседями (разница ≤ 5, третье гнездо ≥ на 2 дальше), `far` — остальные спорные перекрёстки (два и более гнезда в 14 тиках). Не тупики. Выбор жадный: сначала колонии с наименьшим
   суммарным делимым снабжением (корзины по 1.5 ед./тик), затем кандидат с ближайшим вторым гнездом. Владения и «своих» площадок нет — `PatchSpec.zone` лишь метка происхождения.
5. **Узкие места.** Мост, разделяющий гнёзда с обеих сторон, получает `lane_cap = 4` и `chokepoint`.
6. **Перемешивание id.** `node_id` и `colony_id` вытягиваются из RNG: порядок id не несёт роли (тест: наборы id гнёзд и `near`-площадок различаются между картами, `nests` не отсортированы).
7. **Приёмка.** Раскладка принимается, только если `fairness.evaluate` проходит **все** проверки; иначе она отбрасывается и рисуется заново из того же потока (≤ `max_attempts = 40`). Число попыток записано в карте, поэтому
   результат — чистая функция `(config, seed)`. Исчерпание попыток — `MapGenerationError`, а не «лучшая из плохих».

Нет сценарного таймера дефицита, нет «заранее проложенных путей атаки», нет владельцев: в карте только геометрия, длины путей и параметры площадок.

## 4. Ресурсы и сценарии

Параметры из [экономики](ecosystem_v1_economy.md) §3, масштаб `σ` — целочисленные промилле (1500 / 1000 / 600), округление вверх от `.5`:

| Сценарий | near: C / R / Q | border: C / R / Q | far: C / R / Q | Σ регенерации (8 колоний) | на колонию |
|---|---|---|---|---:|---:|
| abundance | 150 / 8 / 15 | 180 / 9 / 18 | 240 / 12 / 24 | 296 | 37.0 |
| moderate | 100 / 5 / 10 | 120 / 6 / 12 | 160 / 8 / 16 | **192** | **24.0** |
| severe | 60 / 3 / 6 | 72 / 4 / 7 | 96 / 5 / 10 | 120 | 15.0 |

Площадки стартуют полными (`start_stock = capacity`). Бюджет проверяется независимо: `resource_budget` в отчёте и тест пересчёта по таблице на каждой из 1800 карт.
Moderate совпадает с экономикой (192 / 24.0); abundance и severe дают 37.0 и 15.0 вместо округлённых «36 / 14.4» из документа из-за целочисленного округления параметров (7.5 → 8, 4.8 → 5) — это следствие
правила округления, а не ошибка.

## 5. Схемы: как реализованы контракты, и отклонения

Все схемы строгие (`codec.py`): неизвестный ключ, недостающий ключ, `true` вместо числа, число > 2⁵³, неизвестный `Literal`, неканонические байты, дубликаты ключей — ошибка загрузки; после неё проверяются инварианты (`validate.py`).
Хэши: `config_hash`, `map_hash` (хэш содержимого без самого поля), `state_hash` (состояние без RNG, привязано к `config_hash` и `map_hash`), `checkpoint_hash` (состояние + все RNG-потоки).

| № | Контракт | Реализация | Почему |
|---|---|---|---|
| 1 | `NodeE1.patch: PatchSpec \| null` | кортеж из 0 или 1 элемента | в canonical JSON нет `null` |
| 2 | `PatchSpec` зоны `home/border/far` (RFC §5.1) | `near/border/far` | «home» подразумевает владение, которого в карте нет (требование FOR-44: нет автоматического владения) |
| 3 | `ConfigE1`: `scenario`, `economy`, `map_params`, `options` | + `resources` (базовые C/R/Q по зонам), + в `MapParams`: `world_side`, `units_per_tick`, `surroundings_per_nest`, пороги справедливости, `contest_radius` | контракты не перечисляли числа генератора |
| 4 | `contest_radius` 12 (экономика §9) | **14** | на реальных картах путь между соседними гнёздами 14–24 тика, площадка в 12 тиках от двух гнёзд встречается редко (подробнее §7); 14 < 16 — предела окупаемости добытчика |
| 5 | `ColonyMemoryE1.nodes[i]` без `node_id`/`kind` | + `node_id` (мировой id за слотом) и `kind` (`unknown` до посещения) | память самодостаточна; политике по-прежнему будут видны только слоты |
| 6 | `AgeLedger` (корзины 100 тиков) | как в контрактах §4.1; старт: возраст `i·500‰·L/n`, корзина — floor-деление (старшая) | экономика §7.1 |
| 7 | `RunStateE1`/потоки | `map` (после генерации) и `world` (не используется правилами) | контракты §3 |
| 8 | Начальные ордера | пустые: `egg_level 0`, нет целей, 3 отряда `none` | «начальная инициализация без симуляции»; ордера задаст E1-b (fixtures) |
| 9 | Скользящие `income/burn/pop_ema` | `0` / `upkeep·Q/10` / `(2W+S)·Q/2`, `Q = 65536` | старт «в равновесии»; формулы определит E1-b |

**Память колоний на тике 0** (`initial_known_radius = 5`): гнездо и все узлы на пути ≤ 5 тиков — *visited*; концы их рёбер — *discovered* (вид неизвестен); чужих гнёзд, колоний, sightings, куч нет. Это проверяется тестом
`test_colony_memory_contains_only_the_local_neighbourhood` на каждой колонии.

## 6. Отчёт справедливости (`--report`)

Все проверки пересчитываются **по готовой карте** (`fairness.evaluate`), а не по внутренним данным генератора; все числа целые (тики, промилле) и хэшируются (`report_hash`).

| Проверка | Порог | Источник |
|---|---|---|
| связность; число узлов; число и зоны площадок; гнёзда различны | — / 80–120 / 24–40 | задача FOR-44, RFC §5.1 |
| путь между любыми двумя гнёздами | ≥ 14 тиков | RFC §5.2 |
| путь от гнезда до ближайшего соседа | ≤ 40 тиков | RFC §5.2 |
| `near`: путь до владельца / отрыв от второго гнезда | 3…6 / ≥ 3 тика | экономика §3 |
| разделяемые площадки оспариваются | ≥ 2 гнезда в 14 тиках | задача FOR-44 (contested patches) |
| CV доступа к `near` (взвешен кпд переноса `φ(d)`) | ≤ 10% | RFC §5.2 |
| CV делимого снабжения в радиусе 10 тиков | ≤ 20% | RFC §5.2 |
| узкие места вблизи гнезда (в 8 тиках) | ≤ 2 | RFC §5.2 |
| доля узких рёбер | ≤ 15% | RFC §5.2 |
| согласованность `lane_cap`/`chokepoint` (мосты пересчитываются) | точное совпадение | контракты §3 |

Фрагмент отчёта seed 42 (moderate, 8 колоний): 96 узлов (56 перекрёстков), 164 ребра (длина 2…6), 32 площадки (16 / 8 / 8), расстояние до ближайшего гнезда-соседа 16…18 тиков, регенерация 192 ед./тик
(24.0 на колонию), CV доступа к `near` 6.6%, CV делимого снабжения 18.3% (в пределах 20%), попыток 2, **все проверки пройдены**. Полный отчёт — в `docs/ecosystem_examples/map_seed42_moderate_8.json`.

## 7. Что реальные карты говорят об экономических допущениях (для E1-b, не пересмотр дизайна)

Калькулятор [экономики](ecosystem_v1_economy.md) использует идеализированное кольцо (border на 7 тиках от двух колоний, far на 10 тиках от трёх). Измерено на 200 картах (8 колоний, moderate):

| Величина | Калькулятор | Генератор (среднее, диапазон) |
|---|---:|---|
| путь до `near`-площадки | 3 | 3.9 (3…5) |
| путь до ближайшего / второго гнезда у `border` | 7 / 7 | 8.3 (5…13) / 10.2 (7…14) |
| колоний в радиусе 10 тиков от `border` | 2 | 1.5 (0…2) |
| путь до ближайшего / второго / третьего гнезда у `far` | 10 / 10 / 10 | 7.9 (5…14) / 12.0 (8…14) / 19.5 (11…35) |
| колоний в радиусе 10 тиков от `far` | 3 | 1.0 (0…2) |
| делимое снабжение в радиусе 10 тиков на колонию | 24 | 23.1 (13…31) |
| путь между ближайшими гнёздами | 14 | 17.3 (14…24) |

Вывод: ограничение «гнёзда не ближе 14 тиков» (RFC §5.2) вместе с реальной длиной путей по графу делает спорные площадки заметно дальше, чем в калькуляторе: `border` — в основном двусторонние на 8–10 тиках,
`far` — зона 12–14 тиков, где кпд переноса `φ ≈ 0.45–0.5` (чистая прибыль добытчика ≈ +0.1). Средний бюджет близок к расчётному (23.1 против 24), но **конфликтная зона дальше и тоньше**, чем в калькуляторе. Это входит
в задачу калибровки E1-b/E1-c (коридоры C3–C4, C7 экономики §9): пересчитывать надо числа документа (erratum), а не подгонять карту молча. Здесь расстояния не менялись.

## 8. Производительность (только генерация, `bench`, 100 карт, Windows 11, Ryzen 5 7600X, Python 3.12.10, один поток)

| Колоний (узлов) | Генерация с приёмкой: среднее / медиана / p95 / макс. | Отчёт справедливости на готовой карте: среднее / p95 | Попыток: среднее / макс. |
|---|---|---|---|
| 6 (80) | 10.9 / 8.8 / 24.7 / 40.1 мс | 0.37 / 0.42 мс | 2.56 / 10 |
| 7 (88) | 13.0 / 9.7 / 30.8 / 40.1 мс | 0.46 / 0.63 мс | 2.40 / 7 |
| 8 (96) | 11.6 / 7.3 / 23.7 / 51.0 мс | 0.52 / 0.65 мс | 1.84 / 9 |

Это **латентность генерации карты**, не «миров в секунду»: симуляции нет. Хвост (p95 ≈ 3× медианы) — перегенерация отклонённых раскладок (одна попытка ≈ 5–6 мс). Оптимизации по профилю: ограниченное множество пар-кандидатов для MST (результат побайтно
тот же), предвычисление рангов кандидатов, план кодирования по классам в кодеке. Тест `test_generation_latency_stays_in_a_sane_range` лишь страхует от квадратичных регрессий (порог 250 мс/карту).

Полный набор тестов E1-a (`tests/test_eco_*`): генерация 1800 карт занимает ≈ 35–40 с, остальное — секунды.

## 9. Тесты (`tests/test_eco_*.py`)

* **Генерация** — связность; уникальность гнёзд; детерминизм и различие по seed; независимо пересчитанные (свой Dijkstra, дроби вместо целочисленных CV, перебор мостов) пути, спорные площадки, бюджет ресурсов, справедливость, узкие места
  на 200 картах × 3 сценария × 3 размера; planarity на 12 картах; id без роли; перестановка `colony_id` (`permute_colonies`) сохраняет отчёт; отказ при невыполнимом конфиге; плохие seed.
* **Схемы** — строгая круговая сериализация конфига, карты, состояния, checkpoint; golden-хэши; подделка карты, чужой конфиг, рассинхронизация хэшей; 28 нарушений инвариантов состояния; память без скрытой информации.
* **CLI** — стабильность вывода, `verify` ловит подделки (включая карту с пересчитанными хэшами, не порождённую генератором), `bench`, `sweep`, коды выхода, воспроизводимость закоммиченного примера.
* **Изоляция и CI** — AST-проверка импортов в обе стороны (самопроверка детектора на 22 синтетических случаях), неизменность контрактов L0, непересечение доменов хэшей, политика путей CI.

Golden-хэши (seed 42, moderate, 8 колоний) — регрессионные значения, выданные реализацией; авторитетными они становятся после ревью: `config_hash 05a9b71d…e909`, `map_hash fce2596c…600d`, `state_hash 03ac8f74…2d81`.

## 10. Политика CI (PR-0, объединён с PR-1)

`scripts/ci_historical_policy.py` теперь считает «независимыми» (быстрый путь) ещё пути `src/formicmind/eco/`, `tests/test_eco_`, `tests/test_ecosystem_`, `docs/ecosystem_`, `scripts/ecosystem_`. Безопасность держится на трёх вещах:

1. **Граница импортов** доказана AST-тестом в обе стороны (§2); она же выполняется в обычном полном `pytest` на Windows.
2. **Fail-closed для всего остального:** любой иной или смешанный путь (L0, `pyproject.toml`, `.github`, результаты) остаётся чувствительным; добавлена защита от обхода (`..`, `.`, `//`, абсолютные пути и диски считаются чувствительными).
3. Существующие проверки не отключены и не переименованы: те же пять jobs (`Windows CI`, `Viewer`, `Historical sensitivity gate`, `Historical FOR-25`, `Historical FOR-35`).

Так как этот PR **меняет саму политику** (`scripts/ci_historical_policy.py`), он чувствительный, и закреплённые FOR-25/FOR-35 в нём выполняются (требование FOR-44). Следующие eco-only PR получат быстрый путь.

## 11. Известные ограничения и следующий шаг

* Нет движения, добычи, цикла экономики, боя, разведки в динамике, наград, наблюдений/масок/действий (E1-b, E1-c, E2).
* Генератор даёт карты, в которых спорная зона дальше, чем в калькуляторе (§7): E1-b должен сверить коридоры C3–C4 с реальными путями.
* `chokepoint` встречается примерно на трети карт (66–75 из 200 у 8 колоний), у 6 колоний — на 28%; это свойство структуры графа, а не настраиваемая величина.
* Размер `world_side`, плотность «окрестности гнезда» и пороги справедливости — кандидаты (`eco1-candidate-unvalidated`), как и все числа баланса.
* Следующий шаг по плану: **E1-b — живые колонии и логистика** (тик, когорты, перенос добычи, склад, старение, кладка, голод, ledger сохранения еды).
