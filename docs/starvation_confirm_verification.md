# FOR-35: современные тесты и историческая воспроизводимость

Результаты FOR-35 (`results/starvation_confirm`, вердикт «недостаточно данных») привязаны к конкретному движку: fingerprint `src/formicmind/**/*.py` без двух исследовательских харнессов равен `ff8b73e4a0a2cbd5f7638e3b56bc590a76dc427c36ff19aac11337dd02ca0611` (база `0bb12ad`). Пакет `main` растёт законно (ML-модули PR #18, следующие исследования), поэтому проверки разделены так же, как в FOR-25 ([starvation_debt_verification.md](starvation_debt_verification.md)). Исходный протокол, erratum E1/E2, 4800 строк результатов и замороженный fingerprint не менялись.

## Две разные проверки

| | Современная (обычный `pytest`, job `test`) | Историческая (job `historical-for35`) |
| --- | --- | --- |
| Что проверяет | Свойства, не зависящие от остального содержимого пакета: арифметику вариантов, метрики стагнации, кластеры и E1, K0–K7, вердикт, `verify-static`, tamper-тесты, алгоритм fingerprint на синтетическом дереве | Воспроизводимость: `preflight` (в том числе равенство fingerprint движка замороженному) и полная регенерация |
| Движок | текущий, любой, пока физика не нарушена | замороженный, закреплённый SHA |
| Регенерация матчей | нет (кроме нескольких матчей вне расписания, seed `20270301`) | да, все 4800 матчей и 960 якорей, побайтное сравнение |
| Требует равенства всего пакета замороженному fingerprint | **нет** | **да** |

`python -m formicmind.starvation_confirm verify-static --input results/starvation_confirm` проверяет хеши протокола, erratum, артефактов и манифеста, расписание, бюджет, якоря и то, что `summary.json` ровно следует из сохранённых строк. Это **не** воспроизведение: ни один матч не пересчитывается. Полную проверку делает `verify`; на изменившемся дереве `preflight` и `verify` отказывают с пояснением (fingerprint движка отличается), а не молча.

## Закреплённый коммит

Историческая CI-задача берёт коммит `3139c7b953c38d96d35e0baf2267781138ebcb71`: в нём лежат исходные результаты, исходный строгий verifier и исходный модуль тестов; на нём `verify` проходит локально (4800 строк, 960 якорей). Закрепление — полный SHA, а не ветка, с проверкой `HEAD` в начале задачи. Не менять SHA вслед за `main`: другой SHA означал бы другие результаты и требует нового протокола.

Шаги задачи: `preflight` (протокол, erratum, fingerprint, seeds) → исходный `tests/test_starvation_confirm.py` без пропусков → `verify --workers 4` (полная регенерация). Локальные Git worktree для этого не создаются.

## Что менялось после ревью PR #19

* Современные тесты больше не требуют `source_fingerprint(...) == BASE_ENGINE_FINGERPRINT`; равенство проверяется только историческим `preflight`/`verify` на закреплённом коммите.
* Поиск коллизий seeds вынесен в чистую функцию `find_seed_collisions` (тест на синтетических файлах); сканирование всего репозитория остаётся условием исторического `preflight`.
* Тест структуры CI требует наличия задач `test`, `historical-for25`, `historical-for35`, Windows для каждой, `timeout-minutes` у каждой и закреплённые SHA, а не фиксированное число задач.
* Добавлен отдельно помеченный post-hoc анализ чувствительности без просмотренной группы расписания: `results/starvation_confirm_posthoc/sensitivity_without_previewed_group.json`. Он удаляет все строки seed `20270501` пары `turtle–raider` на `R0-T0` (оба места, все варианты) и пересчитывает предрегистрированные анализы без проверки целостности расписания. Формальный вердикт и 4800 строк не затрагиваются. Результат: исключение не меняет ни число кластеров экспозиции (`E = 3`, та же тройка ячеек, кластер `R0-T0 turtle–raider` остаётся с 7 seeds), ни классы разрешения, ни критерии K3–K7, ни вердикт «недостаточно данных»; это проверено, а не предположено.
