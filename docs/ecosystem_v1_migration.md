## 1. Версия среды и изоляция от L0

Ecosystem v1 — **новая среда**, а не новая версия L0. L0 остаётся «ареной и лабораторией RL» (видение §13): 2 колонии, 7 узлов, `ObservationV2[223]`, `ActionV2`, известный enemy home.

| Что | L0 (не меняется) | E1 |
|---|---|---|
| Пакет | `formicmind.*` (`rules`, `tick`, `combat`, `observation`, `actions`, `decoder`, `replay`, `ml`, `rl`) | `formicmind.eco.*` (новый каталог `src/formicmind/eco/`) |
| Тесты | `tests/test_*.py` | `tests/test_eco_*.py` |
| Версии | `l0-proto-FOR1-v0.2.2`, `candidate-FOR1-v0.2.1-unvalidated`, `ObservationV2`, `ActionV2`, checkpoint v3 | `eco1-proto-v0`, `eco1-candidate-unvalidated`, `ObservationE1/v1`, `ActionE1/v1`, `formicmind.eco.checkpoint/1`, `eco-replay/v1` |
| Хэш-домены | `formicmind/{config,state,checkpoint,events}/v1…v3` | `formicmind/eco/{config,map,state,checkpoint,events}/v1` |
| Seed-диапазоны | обучение `4.2·10⁹`, оценка `≥ 9·10⁹` (FOR-42) | обучение `5.2·10⁹…`, оценка `≥ 9.5·10⁹`, карты held-out — отдельный диапазон |
| CLI | `sim`, `formicmind-ml`, `python -m formicmind.replay|rl` | `python -m formicmind.eco …` (новая точка входа, добавляется в E1-a) |

**Правила изоляции (проверяются автоматически):**

1. `formicmind.eco` импортирует из L0 только `canonical` и `rng`. Ни один модуль L0 не импортирует `eco`. Тест `test_eco_import_boundary` (AST-проверка импортов) — часть PR-0/PR-1.
2. Файлы L0 (`src/formicmind/*.py` вне `eco/`), `versions.py` и golden-хэши не редактируются PR-ами E1. Тест `test_l0_pins_unchanged` сравнивает `CONTRACT_PINS`, `RULES_VERSION`, golden `state_hash` с зафиксированными значениями.
3. Исторические результаты (`results/starvation_*`, `results/ml_*`, `results/rl_for42/`) и пины FOR-25/35 не меняются; CI-проверки `FOR-25 manifest`, `FOR-35 static` остаются без изменений.
4. Checkpoint/replay E1 имеет другую схему; загрузчики L0 отвергают её по тегу схемы, загрузчики E1 отвергают схемы L0.
5. Чекпоинты RL L0 и FOR-42 **нельзя** загрузить в E1 (другие вход/выход); перенос — только через явное преобразование (видение §9), которое в v1 **не** планируется.

## 3. Дорожная карта и соответствие этапам видения/issue

Этапы видения §12: **E0** RFC и баланс (этот PR) → **E1** живой мир без нейросети → **E2** интерфейс агента + replay/viewer → **E3** PPO + multi-agent league → **E4** масштаб и история.

> **Решение V-6 (принято, RFC §15.1).** В issue FOR-43 E2 описан как «local conflict/scouting & viewer»; в видении (основной документ) туман войны и агрессивные действия входят в **E1**, а E2 — это
> интерфейс ObservationE1/ActionE1, replay и viewer. План ниже **следует видению**. Если владелец вернётся к тексту issue — PR-3 (туман+конфликт) переезжает в E2 без других изменений.

```
E0   этот PR  ─ документы + калькулятор бюджета
 │
PR-0 ─ CI-политика и граница импортов            (подготовка, ≤ 1 дня)
 │
E1   PR-1  основание и карта                      ┐ «Живой мир без нейросети»
     PR-2  живой мир: когорты, добыча, экономика  │  (headless, scripted fixtures)
     PR-3  туман войны, разведка, конфликт        ┘  ← ПЕРВАЯ РАБОТАЮЩАЯ ЭКОСИСТЕМА
E2   PR-4  ObservationE1/ActionE1, replay, viewer
E3   PR-5  модель и ядро PPO на игрушках          ┐  ← ПЕРВАЯ ОБУЧАЮЩАЯСЯ ЭКОСИСТЕМА
     PR-6  multi-agent self-play, лига, оценка    ┘
E4   (вне этого плана) масштаб, длительные миры, архив стратегий
```

«Первая работающая экосистема» = завершён PR-3: 8 колоний живут, растут, голодают, исследуют, торгуют ударами (при fixtures) и исчезают; воспроизводимо и в коридорах экономики.
«Первая обучающаяся» = PR-6.

## 4. Последовательность PR и небольших задач

Каждая задача — ≤ 1 рабочего дня, с проверкой. Идентификаторы `E1a.n` — рабочие метки для Linear. Размеры — оценки порядка величин. **CI-класс** — по `scripts/ci_historical_policy.py`: неизвестные
пути «чувствительные» (полные FOR-25/FOR-35, ≈ 14 мин), белый список (`src/formicmind/ml/`, `tests/test_ml_`, `viewer/`, `docs/ml_`, `docs/ci_strategy.md`) — быстрые.

### PR-0 — CI-политика и граница импортов (подготовительный)
Цель: чтобы работа над `eco` не запускала по 14 минут исторической регенерации в каждом PR **без** снижения защиты L0.
* E0.1 Добавить в `_INDEPENDENT_PREFIXES`: `src/formicmind/eco/`, `tests/test_eco_`, `docs/ecosystem_`, `scripts/ecosystem_`, `viewer/` (уже есть). Тесты политики: eco-пути → fast; смесь eco + L0 → sensitive; пустой список → sensitive.
* E0.2 Пустой пакет `src/formicmind/eco/__init__.py` + `test_eco_import_boundary` (AST) + `test_l0_pins_unchanged`.
* Проверка: pytest, Windows CI. **CI-класс:** чувствительный (правит CI/политику). Этот PR — единственный eco-PR, где полный исторический прогон обязателен.
* Риск: белый список для `eco` безопасен только пока работает граница импортов — поэтому оба теста идут вместе.

### PR-1 (E1-a) — основание и карта
> **Статус: реализовано в FOR-44** (вместе с PR-0, по указанию задачи): [ecosystem_v1_map_generator.md](ecosystem_v1_map_generator.md). Отличия реализации от этого плана и измеренные числа — там (§5, §7).

* E1a.1 `eco/versions.py`, `ConfigE1`, `EconomyParams` (целые), `config_hash`. Тест: golden-хэши, неизменность при перестановке ключей.
* E1a.2 Схемы состояния (`MapE1`, `WorldStateE1`, `ColonyStateE1`, `CohortE1`, `ColonyMemoryE1`) + строгая загрузка + `state_hash`/`checkpoint_hash`. Тест: round-trip, отвержение чужих схем (в т.ч. L0).
* E1a.3 Реестр RNG-потоков (`map`, `world`, `policy:<id>:<colony>`) через L0 `rng.py`.
* E1a.4 Генератор карт: узлы, площадки по ролям, рёбра, chokepoints, `fairness_report`; сценарии abundance/moderate/severe; 6/7/8 колоний. Тесты T-02, T-02b, T-16 (генерация), определённость по seed.
* E1a.5 CLI `python -m formicmind.eco map --seed … --colonies 8 --scenario moderate --report` (JSON-отчёт справедливости).
* **Готово, когда:** 200 карт × 3 сценария × 3 размера проходят проверки; отчёт воспроизводим; L0 нетронут. **CI-класс:** быстрый (после PR-0). ~1.2–1.8 тыс. строк с тестами.

### PR-2 (E1-b) — живой мир: когорты, перенос добычи, экономика (без разведки и боя)
* E1b.1 Скелет тика (фазы Hatch/Arrival/Harvest/Upkeep/Lay/Regeneration/Depart), когорты, движение по рёбрам, `lane_cap`-задержка. Тест: ETA, слияние/разделение когорт.
* E1b.2 Добыча с переносом: цикл GO→WORK→RETURN, нейтральное правило делёжа на площадке, `storage_cap`, `harvest_patience`, кучи. Тест T-01, делёж без смещения в порядке колоний.
* E1b.3 Upkeep/голод/кладка/созревание (порядок жертв L0). Тест: известные ответы из `docs/economy.md` на когортах.
* E1b.3a **Старение** (V-4): журнал возрастов (`AgeLedger`), смерть от старости в фазе `Hatch/Age`, разнесённый старт, списание небоевых потерь пропорционально; инвариант «журнал = когорты». Тесты T-17, T-23 (границы корзин: фактическая жизнь ∈ [L − 99, L]), коридоры C11–C12, C14. Состояние колонии хранит фикс-точечные EMA (`income`, `burn`, `pop`) для `v_q(τ)` по тикам.
* E1b.4 Ledger сохранения еды и инварианты после тика (T-03).
* E1b.5 Fixtures `idle`, `fair`, `greedy`, `hoarder` (**только для тестов**; явно помечены; `fair` поддерживает минимальный гарнизон из 2 солдат) + headless-runner + **первый профиль** (T-12, цели §6).
* E1b.6 Калибровка по коридорам C1–C4, C6, C11, C12, C14 экономики §9 — отчёт сравнения «движок vs калькулятор»; диагностические сценарии **D1 `peaceful_fair`, D2 `greedy_scarcity`, D7 `age_replacement`** (экономика §8.2a).
* **Готово, когда:** T-01, T-03, T-04, T-17, T-19 (D1–D2); мир `fair` — 8 из 8 доживают; мир `greedy` — голод без единого скрипта войны; старение укладывается в C11–C12; профиль снят. **CI-класс:** быстрый. ~2–3 тыс. строк.

### PR-3 (E1-c) — туман войны, разведка, конфликт, калибровка → **первая работающая экосистема**
* E1c.1 `ColonyMemoryE1`: сенсорная фаза, слоты, sightings, контакт, старение сведений, стартовая окрестность (контракты §4.3). Тесты: правила записи 0–6.
* E1c.2 Приказы-миссии: `SCOUT`, `GUARD`, `ATTACK` (по паре узел+колония), `WITHDRAW`, `HOME`; кратчайший *известный* путь. Тест T-05 на уровне движка (атака неизвестного гнезда отвергается).
* E1c.3 Бой на пулах HP когорт (multi-party, ответ защитника по силе), матка, потери, `workers_flee`, спил груза. Тесты: паритет с L0-ответами для двусторонних боёв (`docs/combat_terminal.md`), T-08, T-09.
* E1c.4 Смерть матки → `orphan` (стоячие приказы, без решений) → естественное вымирание от старения/голода/боя → `extinct` → куча; терминалы колонии/мира; горизонт. Тесты T-07, T-18, коридор C13, диагностический сценарий **D8 `queen_death_natural`**.
* E1c.5 Fixtures `raider`, `turtle`, `scout`; события (`contact`, `combat`, `death`, `queen_dead`, `extinct`) и `events_hash`; checkpoint/restore (T-10 частично).
* E1c.6 Отчёт калибровки (C5, C7–C10, C13) и **диагностический отчёт конкуренции** — сценарии **D3 `guarded_expansion`, D4 `attack_retreat`, D5 `third_party`, D6 `built_army`** (экономика §8.2a; T-20): отдача еды после транспорта, боевые затраты, воспроизводство; отчёт описывает измеренные выгоды и **не обещает войну**. Заморозка `eco1-candidate-unvalidated`; симметрия T-11.
* **Готово, когда:** выполнены критерии первой экосистемы (§5), включая D1–D8. **CI-класс:** быстрый. ~3–4 тыс. строк; при > 3 тыс. разбить: 3a (память+разведка) и 3b (бой+терминалы).

### PR-4 (E2) — ObservationE1/ActionE1, replay, viewer
* E2.1 Построитель `ObservationE1` (инкрементальный, из памяти) + маски (чистые функции) + корзины силы. Тесты: свойства 1–5 (T-06), размеры блоков.
* E2.2 `ActionE1` + декодер + валидатор + технические ошибки; политики `random`/`fixture` через интерфейс. Тест T-05 по латентам.
* E2.3 Writer/reader/`verify` для `eco-replay/v1`; цепочка хэшей; повторное исполнение (T-10).
* E2.4 Viewer: загрузка eco-replay, граф с 8 цветами, переключатель «все данные / знание колонии c», слои еда/влияние/конфликты, лента событий, панель колонии, перемотка. Vitest на фикстурах от Python writer.
* **Готово, когда:** replay мира из 8 колоний воспроизводится `verify` и смотрится во viewer; слой «знание колонии» построен из `memory`, а не из мира. **CI-класс:** Python-часть быстрая, `viewer/` — быстрый. Размер большой: при ревью делить на 4a (Python) и 4b (viewer).

### PR-5 (E3-a) — модель и ядро PPO на игрушках
Зависит от merge PR #24 (код PPO).
* E3a.1 Сеть: граф-энкодер + GRU + pointer-головы; actor и critic раздельно; профиль параметров и мс/решение. Тесты форм, масок, конечности.
* E3a.2 Распределение и log-prob над ActionE1 (категориальные, pointer без возвращения, logistic-normal доли); `log π` того же латента; полный перебор нормировки на малых масках.
* E3a.3 Награда по **прошедшим тикам мира** (контракты §9.2: `viability_trace`, `r_i`, `r_i^γ`, штраф один раз) + тесты T-21 (независимость от частоты решений), T-13 (idle/hoard/soldier_spam/worker_spam/turtle/suicide_raid) + `reward_reads_only_own_state`; эталонная арифметика — `scripts/ecosystem_reward_ref.py`.
* E3a.4 Рекуррентный PPO (куски по 32, скрытое состояние, **time-aware GAE** с `γ_i = γ_30^(Δ_i/30)`, `λ_i = λ_30^(Δ_i/30)`, bootstrap `Value_critic(o_H)` только при усечении, терминал без bootstrap, padding, KL-мониторинг) + тест T-22.
* E3a.5 Игрушечные задачи с известным ответом (одна колония осваивает home+border быстрее `idle`; pointer выбирает известный узел; награда за выживание) — **ворота A** (RFC §12.3).
* **Готово, когда:** игрушки решены только по награде; тесты утечки и награды зелёные. **CI-класс:** полный pytest (ML smoke), быстрый path.

### PR-6 (E3-b) — multi-agent self-play, лига, оценка, первый запуск
* E3b.1 Параллельный сбор (spawn, Windows): 8 колоний на мир, независимые скрытые состояния и RNG, батч-инференс по колониям.
* E3b.2 Режим `mirror`, затем `league` (снапшоты с SHA-256), посадка политик на гнёзда — случайная перестановка.
* E3b.3 Оценочный набор: ≥ 30 held-out карт × 3 сценария × 8 ротаций; контроли `random/init/idle/fair/greedy/raider/turtle`; метрики RFC §12.3.
* E3b.4 Первый запуск (тысячи миров) и отчёт: что выучено, чего нет, как выглядят конфликты по реальным событиям (**ворота B**); профиль CPU/GPU и план масштабирования (**ворота C — не запускается без одобрения**).
* **Готово, когда:** отчёт содержит честную разницу с `init` на новых seed (любой знак), без утверждений о «возникшей войне» без метрик. **CI-класс:** быстрый.

**Всего:** PR-0 + 6 PR (PR-4 при необходимости делится на два ⇒ максимум 8 ревью). E4 не планируется детально до результатов PR-6.

## 5. Критерии «первой работающей экосистемы» (конец PR-3)

1. 8 колоний на карте ~96 узлов, 6000 тиков, headless, без ручных вмешательств; конфиги 6/7 тоже.
2. Сценарии abundance/moderate/severe воспроизводят коридоры C1–C14 экономики §9 (допуск ±25%).
3. `fair`-мир: нет боёв, все доживают; `greedy`-мир: голод возникает сам; `raider`-fixture ломает мир предсказуемо дорого (потери/голод).
3a. Диагностические сценарии D1–D8 (экономика §8.2a) проходят: знак выгоды нападения/обороны совпадает с калькулятором; сироты вымирают естественно (0.5–1.1 `L`); отчёт не обещает войну.
4. T-01…T-05, T-07…T-11, T-15…T-20 зелёные; T-12 — профиль снят и сопоставлен с целями §6.
5. L0 нетронут (T-15), CI зелёный (Windows), Linear/PR описывают границу.

## 6. CPU, профиль и риски

### 6.1 Что известно (L0, FOR-42; main + ветка PR #24)
* 1 воркер: 6 542 тиков/с (0.11 мс/тик на 2 колонии, 32 юнита); 10 воркеров: 34 650 тиков/с суммарно (≈ 3.5 тыс. на воркер).
* Движок ≈ 80% времени воркера; инференс MLP ≈ 0.93 мс на решение; GPU почти простаивает; система CPU-bound.
* Полные матчи L0 (3000 тиков): 16.6 эпизодов/с при 10 воркерах; короткие (≈ 290 тиков) — 118 эпизодов/с.

### 6.2 Что **не** переносится
Скорость L0 не оценка E1: 8 колоний, граф ~96 узлов, когорты, память и построение наблюдений на переменном графе — другой профиль (видение §11 п.8: «не оценивать миллион матчей по скорости двухколониального L0»). Все цифры ниже — **цели**, не измерения.
