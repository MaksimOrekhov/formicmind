# Ecosystem v1 — интерфейс политик: ObservationE1 → маски → ActionE1 (FOR-48, E2-b)

Реализация контрактов §7–§8 (`docs/ecosystem_v1_contracts.md`) и первый запуск восьми независимых колоний на настоящем мире E1. Здесь нет PPO, reward, GNN/GRU, лиги и ребалансировки экономики — только честный, строго приватный интерфейс, к которому подключается обучаемая политика на следующем этапе (E3).

## Что сделано

| Модуль (`src/formicmind/eco/`) | Роль |
|---|---|
| `observation.py` | `ObservationE1/v1`: строится из **одной** `ColonyStateE1`, её собственных когорт, тика и публичного `ConfigE1`. Не получает ни `WorldStateE1`, ни `MapE1`, ни других колоний. |
| `action.py` | `ActionE1/v1`, `ActionMasksE1`, чистая `action_masks(obs)`, `validate_action(action, masks)`. Не импортирует модель состояния. |
| `decoder.py` | `decode(latents, masks) -> ActionE1` для любого конечного вектора из `LATENT_SIZE = 818` чисел; `PolicyOutputError` на NaN/inf/не числах/неверной длине. |
| `apply.py` | Единственное место, где действие трогает мир: через валидируемые `order_scout/guard/attack/withdraw` и диспетчер добычи. |
| `policy.py` | Контракт `PolicyE1`; `RandomValidPolicy`; `ObservationHeuristicPolicy` (fixture-адаптер только по наблюдению); `PolicyRunSpec` (кто и с каким seed решает за колонию). |
| `policy_run.py` | `PolicyController` (контроллер движка), журнал решений `DecisionLog`, `run_policies`. |
| `replay_file.py`, `cli.py` | `export_policy_replay`, `python -m formicmind.eco policy-run`, `replay-verify --decisions`. |

Приватность держится на структуре, а не на дисциплине: у функции `build_observation` параметры `colony, cohorts, tick, config, decision_index, ticks_since_last_decision, window, rolling`; в `observation/action/decoder/policy` нет импорта мира, карты и движка и не употребляются имена `world_map`, `state.colonies`, `routes` (тест разбирает исходники AST-ом). Мировые id никогда не покидают память колонии: везде **локальные слоты** (слот 0 узлов — собственное гнездо), число колоний мира, число узлов и RNG в наблюдении отсутствуют.

## ObservationE1/v1 (как реализовано)

* `global_features[40]` — индексы §7.1; `node_features[n,24]` (§7.2), `edge_features[m,6]` + `edge_slots`, `foreign_features[f,12]` (f ≤ 7, слот по порядку первого контакта) + `foreign_nest_slots`, `cohort_features[c,14]` (только свои; 14-й признак — фаза миссии) + `cohort_slots` (слот узла, слот цели), `sighting_features[s,6]` + `sighting_ints` (узел, колония, возраст), `event_features[e,8]` + `event_ints` (код, слот узла, слот колонии). Хранятся только валидные строки (дополнение нулями — задача загрузчика батча).
* `node_ints[n,4]` = `(kind_code, visited, age, path_ticks)` и `facts` (целые: еда, расход, число рабочих и солдат, **простаивающие у гнезда** рабочие и солдаты, разведчики, расплод, флаг боя) — целочисленные дубли признаков, нужные маскам и декодеру без округления float. `path_ticks` — кратчайший путь от гнезда по **известным** рёбрам (−1 — пути нет).
* Все числа — `float32` и считаются только правильно округляемыми операциями IEEE (без `libm`): нормировка «log» — кусочно-линейный `log2(1+n)`. Поэтому у наблюдения единственная каноническая байтовая форма (`observation_bytes`, `observation_hash`) и она одинакова на всех платформах.
* Переполнение: > 128 узлов, > 320 рёбер или > 7 чужих — `ObservationError` (на штатных картах 6–8 колоний ~40–60 узлов). Если собственных когорт больше 48, остаются 48 крупнейших (число пропущенных в `facts.cohort_overflow`).
* Окно учёта и скользящие средние: при решении закрывается окно последних Δ тиков (`next_rolling`, целочисленные EMA 1/4), наблюдение строится уже с обновлённым значением, а запись в состояние колонии происходит только на этапе применения.
* Особые случаи: первый тик (нет чужих, нет sightings), отсутствие площадок/соседей (маски единственного варианта), устаревшие sightings (возраст ≥ 150 исключает цель), гнездо найдено/не найдено, `alert` (флаг `in_combat_now` по памяти колонии, та же логика, что у движка), матка мертва — `ObservationError`: решений нет.

## Маски (чистые функции наблюдения)

`forage_target`: посещённая площадка, не своё гнездо, известный путь. `scout_target`: не слот 0, есть путь, не посещён **или** возраст сведений ≥ 90. `guard_target`: посещённый узел с путём. `attack_target`: пары `(узел, колония)` — свежий (≤ 150 тиков) sighting **или** найденное гнездо, путь по известному графу; список ≤ 32 + 7, колония — всегда **слот** уже встреченной колонии, поэтому неизвестная колония не может быть целью, а известная не пропадает из маски, если она умерла, и колония этого не знает. Ветви-«вырожденцы» сжимаются: нет целей → `forage_frac` только 0; нет простаивающих рабочих → `scout_n` только 0; нет простаивающих солдат → отряд только `none/withdraw`.

## Декодер

`LAYOUT` задаёт головы: 4 яйца, 5 доля солдат, 9 доля добытчиков, 5 разведчики, 2 бегство, k=0..3 целей добычи, 3 логита долей, 2 числа целей разведки, указатели по 128 узлов (добыча, разведка), на каждый из трёх отрядов — миссия(4), размер(5), указатель охраны(128), указатель атаки(39). Выбор жадный (arg-max, равенство → меньший индекс). Единственный легальный вариант принимается без логита; невозможная ветвь пропускается; цели без возвращения по убыванию логита; доли добытчиков — кусочно-линейный `exp2` в `Fraction` (кратные 1/16, каждая ≥ 1, сумма 16); отряды последовательно делят простаивающих солдат (отряд без солдат становится `none`). Семплирование для обучения (E3) использует те же головы и маски.

## Применение: порядок и атомарность

1. **Решение** (мир не меняется): все решающие колонии (плановое решение — все живые, внеочередное — колонии в бою) получают наблюдение с **одного снимка** мира; политика каждой колонии видит только `(obs, masks)`; ответ — латенты (→ `decode`) или `ActionE1` (→ `validate_action`). Ошибка политики оставляет мир как был.
2. **Применение** (атомарно): колонии по возрастанию id; внутри колонии: запись постоянных приказов → `WITHDRAW` → разведчики → `GUARD/ATTACK` → добыча (берёт рабочих, которых не взяли разведчики). Приказ, идентичный выходящему отряду, не отправляется повторно; отряд, которому не осталось простаивающих солдат, ничего не делает. При любой ошибке возвращаются когорты, приказы и накопители, события отбрасываются, поднимается `PolicyApplyError`: **техническая** ошибка, не поражение. Колонии двигают только свои юниты, поэтому порядок колоний не меняет результат (тест).
3. Сироты не решают; на плановом решении они повторяют последний план добычи (стоячие приказы, контракты §5). Боевая физика, логистика и демография не менялись.

## Воспроизводимость, replay, viewer

* Каждой колонии принадлежит своя политика и свой поток PCG32 `policy:<kind>:<colony>` от `policy_seed` (стандартная деривация `formicmind.rng`); спецификация записана в заголовок replay.
* `DecisionLog` — цепочка хэшей записей `{tick, colony, kind planned|alert, index, obs (хэш), action (слоты), action_hash}`. Мировых id в записях нет. Файл решений — sidecar; replay хранит `decision_count` и `decisions_hash`.
* Replay — обычный `formicmind.eco.replay/1` (`fixture = "policy"`, `roles` = политики колоний, `header.policy` и `result.decision_count/decisions_hash` — единственные добавленные ключи); существующий viewer читает его без mock и показывает чип «независимые политики …», движения, разведку, контакты, бои. `replay-verify --decisions` повторно исполняет мир и требует побайтного совпадения replay и sidecar. Контроллер умеет `snapshot()/restore()`: возобновление из checkpoint даёт те же хэши.

## Запуск

```bash
python -m formicmind.eco policy-run --seed 50012 --policy heuristic:explorer --policy-for 1=heuristic:aggressor --policy-for 3=heuristic:aggressor --policy-for 4=heuristic:peaceful --policy-for 5=heuristic:aggressor --policy-for 6=random_valid --policy-for 7=heuristic:raider --policy-seed 5 --ticks 3000 --frame-every 40 --decisions run.decisions.jsonl --out run.jsonl --verify
python scripts/ecosystem_policy_runs.py --out docs/ecosystem_examples/for48_policy_runs.json
```

Готовый replay для viewer: `viewer/public/samples/eco_policy_seed50012.jsonl` (кнопка «Пример: независимые политики»). Сводка четырёх миров (каждый запущен дважды, хэши совпали): `docs/ecosystem_examples/for48_policy_runs.json`.

## Политики и что они не обещают

* `random_valid` — равномерные латенты → `decode`; не обязан выживать (в мире 50004 все восемь вымирают к тику 114 — мир завершается).
* `heuristic:{peaceful,explorer,raider,aggressor}` — диагностический адаптер фикстур по `ObservationE1`: честная экономика, разведка, налёт на найденное гнездо, `aggressor` — намеренно безрассудная проверка пути атаки (чтобы в replay были бои). Это проверка интерфейса, а не учитель: экономика адаптера слабее экономики фикстур.

## Профиль (один мир, Windows, Python 3.12)

Построение наблюдения ≈ 0.5 мс (≈ 9 КБ, ~40 узлов), маски ≈ 0.02 мс, декодер ≈ 0.15 мс на решение; 8 колоний × 3000 тиков с эвристикой ≈ 2 с (≈ 650 решений). Ничего не оптимизировалось.
