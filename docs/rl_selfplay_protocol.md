# FOR-42 — протокол пилота PPO / self-play (зафиксирован до обучающих прогонов)

Цель: первый RL-агент FormicMind, который **сам** выбирает действия, получает награду только за исход своих
матчей и обновляет веса через actor–critic PPO-Clip в self-play. Это пилот с возможностью масштабирования, а не
обещание роста винрейта. Реализация — пакет `src/formicmind/rl/`, запуск — `python -m formicmind.rl`.

## 1. Инварианты (не нарушаются)

- Единственный источник истины — исходный движок: `reset`, `step_tick` FULL, `ObservationV2` (223 float32),
  `ActionMaskV2`, `ActionV2`, общий `decode_action_logits` (17 float32 → `ActionV2`), K=30, `T_max=3000`.
  Физика, правила, `rules_version`, балансы, декодер, форматы и базовые боты не менялись (diff по `src/formicmind/*.py`
  вне `rl/` пуст).
- Вход политики — только легальное `ObservationV2` (маска вычисляется из него же). Ни скрытого состояния оппонента,
  ни меток Balanced v2: **ни одно решение или логит Balanced/любого бота не используется как target loss**. Датасеты
  FOR-37/38/40 в обучение не входят, held-out FOR-40 не используется.
- Фиксированные боты (`random/turtle/rush/balanced/raider` v2) — только *независимые оценочные противники* в отдельных
  не обучающих матчах. В обучающем self-play их нет (`baseline_sparring = 0`); опция существует для отдельных
  экспериментов и в пилоте выключена.
- Технический сбой контроллера (исключение, невалидное действие) пробрасывается и останавливает запуск; он никогда не
  становится поражением, ничьёй или наградой.

## 2. Распределение действий и `log_prob` (фаза 0)

Декодер детерминирован, поэтому сэмплируется **латентное действие**, а исполняемое `ActionV2` — детерминированная
функция латента (`latent → 17 logits → decode_action_logits`). PPO использует `log π(латент | obs, mask)`; argmax-лог-
вероятность не применяется. Реализация и вывод — `rl/distribution.py` (docstring).

| Компонента | Распределение |
|---|---|
| `lay` (3) | Categorical по разрешённым маской |
| `army` (7) | Categorical по достижимым (маска) |
| `avoid_center` | Bernoulli(σ(avoid[army])) **только если** маска разрешает обе опции для выбранного `army`; иначе значение принудительное, log-prob = 0, энтропия = 0 |
| поддержка forage `k∈{1,2,3}` | Categorical, замаскирован `k ≤ #допустимых целей` |
| цели forage | упорядоченный кортеж из `k` различных допустимых целей, последовательно без возвращения (Plackett–Luce) |
| доли forage | logistic-normal: `z_j ~ N(μ[t_j], σ[t_j])`, доли `softmax(z)` → квантование Q=65535 штатным декодером |

Латент → логиты: lay/army — выбранный индекс 1.0, остальные 0.0; avoid — ±1.0; цели forage — `z_j − min(z) + 1.0`
(строго положительные, ровно `k` штук), остальные `−1.0` (тогда `k = min(3, max(1, #положительных))` и softmax по ним
даёт `softmax(z)`). Если квантование округляет крошечную долю до нуля, исполненная поддержка уже латентной — это тоже
детерминированная функция латента, ratio остаётся корректным.

Энтропия для бонуса — оценка по цепному правилу (условные энтропии вдоль выбранного префикса), раздельные
коэффициенты для дискретных голов и гауссовых долей. Тесты: нормировка дискретной массы (полное перечисление), независимая
float64-переформулировка `log_prob`, частоты сэмплирования, маски/принудительный avoid, round-trip через декодер на
реальных масках и валидатором, конечность на экстремальных логитах, градиенты, ratio=1 при тождественных весах.

## 3. Модель

`ActorCritic`: actor `223→256→256→256` (tanh, ортогональная инициализация) + линейная голова 32 выходов
(lay 3, army 7, avoid 7, k 3, targets 6, share_mu 6) + обучаемый `log_std[6]`; **отдельный** critic
`223→256→256→256→1` (без общих параметров). ~197k параметров actor, ~189k critic. Нормализации наблюдения нет
(значения `ObservationV2` уже в [0,1)). Инференс на CPU использует только actor.

## 4. Награда (фаза 1)

- Терминал: победа +1, ничья 0, поражение −1 с точки зрения места агента (`2·score−1`), сумма двух мест в зеркальном
  self-play = 0. Реальный таймаут `T_max` — это **ничья (0)**, а не усечение.
- Усечение harness (`max_ticks`, `outcome is None`; только кратно K) — **без** терминальной награды: последний шаг
  bootstrap-ится значением `V(obs на отсечке)`. В пилоте матчи полные, усечений нет.
- Награда приписывается решениям политики (раз в K тиков), `γ` — в решениях.
- Shaping (по умолчанию выключен, `shaping_coef = 0`): потенциал `Φ = coef·(queen_hp + worker_hp_sum + soldier_hp_sum)/3`
  только по собственным публичным признакам, `r' = r + γΦ(o') − Φ(o)`, `Φ(терминал)=0`, `coef ≤ 0.5` проверяется,
  суммарный вклад ограничен `2·coef`. Никаких штрафов за «не атакует/мало рабочих», наград за ресурсы без цели.
  Пилот P1 — только терминал; P2 — абляция `coef = 0.05`.
- Тесты: терминальная нулевая сумма, усечение без награды, телескопирование и границы shaping, idle ⇒ ничья 0.

## 5. PPO и self-play (фаза 2)

PPO-Clip (clip 0.2), GAE (γ=0.997, λ=0.95), value loss 0.5·MSE (коэф. 0.5), энтропийный бонус 0.01 (дискретные) /
0.001 (доли), нормализация advantage по батчу, градиентный клип 0.5, Adam lr 3e-4 (eps 1e-5), 4 эпохи, minibatch 512,
ранняя остановка по `approx_kl > 0.05` (среднее за эпоху). Каждая итерация: 128 полных матчей текущими весами → обучение
**только на этих свежих данных** → данные выбрасываются (нет stale-траекторий). Перед обновлением логируется
`identity_ratio_max_dev` (отклонение ratio от 1 при тождественных весах: CPU-сэмплирование vs GPU-пересчёт).

Self-play: оппонент = текущие веса (p=0.5, зеркало, данные обоих мест) либо замороженный snapshot (p=0.5, равномерно из
не более 12 активных; snapshot 0 — необученная инициализация; новый snapshot каждые 5 итераций; неизменяемые файлы с
SHA-256). Данные frozen-оппонента в батч не попадают. Планировщик — чистая функция `(run_seed, iteration)`; каждый
матч имеет уникальный seed `4_200_000_000 + номер матча`; RNG-потоки политик `policy:rl-current:{0,1}` /
`policy:rl-snap-NNNN:0` не зависят от места и друг от друга.

Карты (физика/баланс не меняются — только длины и наличие рёбер зеркально-симметричной топологии, ≤4 для
`ObservationV2`): обучение — `classic, cross, fast_wings, slow_center, wide_ring, shortcut` + процедурные `gen:0…999999`
(50%); **held-out** — `dense, far_flank, chain` + `gen:1000000…1999999`. Мир детерминирован, поэтому разнообразие даёт
независимый policy-RNG и топологии, а не world seed.

## 6. Независимая оценка

Фиксированный набор матчей (seed = функция метки, диапазон `≥ 9_000_000_000`, не пересекается с обучением):
противники `random/turtle/rush/balanced/raider` v2 + `init` (необученная политика) + старые snapshots (suite `full`);
оба места; карты: `classic` (in-distribution) и held-out. `quick` (во время обучения, каждые 10 итераций, только
мониторинг): 5 баз × 5 карт × 2 места + init. `full` (после обучения): 11 карт, 2 повтора, режимы `sample` (стохастическая
политика) и `greedy` (мода). Результаты — `eval/*.json`: win/draw/loss, score, причины завершения, длина, финальные
солдаты/рабочие/еда, частоты действий. Веса по eval-данным **не обновляются**, гиперпараметры/награда/архитектура по
eval не подбираются (параметры ниже фиксированы заранее).

## 7. Бюджет и запуски

Измерение производительности (до обучения, `results/rl_for42/bench_*.json`): сбор на 10 spawn-процессах, профиль одного
процесса; узкое место оптимизируется только если найдено профилировщиком (движок менять нельзя).

| Запуск | Назначение | Бюджет |
|---|---|---|
| S0 smoke | ненулевое PPO-обновление, весь контур | 4 итерации × 32 = 128 матчей |
| P1 | основной пилот (терминал-only), seed 42 | 80 итераций × 128 = 10 240 матчей |
| P1b, P1c | повторы того же протокола, seeds 43, 44 | по 10 240 |
| P2 | абляция shaping 0.05, seed 42 | 10 240 |

Остановка по первому из лимитов (итерации/матчи/wall-clock 3 ч на запуск). Checkpoint каждые 5 итераций, resume
побитово воспроизводим (тест).

## 8. Критерии (технические, не научные)

Технические (все обязательны): T1 — нет ошибок контроллера/невалидных действий/NaN, запуск завершён; T2 — веса изменились
от PPO-обновлений по наградам, все потери конечны, `identity_ratio_max_dev < 1e-3` на каждой итерации; T3 — checkpoint
→ resume воспроизводит веса побитово; T4 — разнообразие сэмплируемых действий в первых итерациях: встречаются все
`lay`, ≥5 из 7 `army`, поддержка forage 1/2/3.

Наблюдаемый сигнал обучения: L1 — на `full` (sample, все карты) счёт против необученной `init` в финале ≥ 0.60; L3 —
поведение изменилось (полная вариация распределений lay/army между первой и последней итерацией ≥ 0.10). L2 (динамика
счёта против пяти ботов относительно `init`) — только отчёт, без порога.

**GO** пилота: T1–T4 и L1 и L3 в основном запуске P1 и не менее чем в одном из повторов. Иначе **NO-GO** с
воспроизводимым баг-репортом и описанием узкого места. Рост винрейта против ботов не заявляется заранее и не является
критерием.

## 9. Масштабирование (после подтверждения корректности)

Отдельная задача: 100k / 1M матчей. Подготовка: профиль и пропускная способность ложатся в `bench_*.json`; сбор
линейно масштабируется числом процессов (движок ≈ 80% времени воркера, GPU занят только в коротких обновлениях);
