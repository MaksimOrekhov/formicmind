# L0 foundation (FOR-9): контракты, модель, reset, RNG, сериализация

Статус: прототип. Игровые числа — **кандидаты** FOR-1 v0.2.1, не утверждённый баланс; Gate 0
не пройден. Всё, чего нет в спецификациях, ниже помечено как **выбор** (engineering choice),
а не как решение FOR-1/FOR-2.

## 1. Зафиксированные контракты

Linear-документы изменяемы, поэтому записаны URL и `updatedAt` прочитанной редакции
(`src/formicmind/versions.py`, `CONTRACT_PINS`). Приоритет: errata выше тела документа.

| Ключ | Документ | updatedAt |
|---|---|---|
| `FOR-1-v0.2.1` | World Specification v0.2.1 (тело v0.2 + errata A–G) | 2026-11-02T12:31:31.981Z |
| `FOR-2-v0.2` | Agent Contract v0.2 | 2026-11-02T13:03:45.716Z |
| `FOR-2-errata-v0.2.1` | Agent Contract errata v0.2.1 (обязательна, приоритет над v0.2) | 2026-11-02T13:22:38.736Z |

Методология FOR-4 и архитектура FOR-5 — справочные основания, к коду не привязаны.
SHA-256 выгруженного markdown документов **не** записан (текст получен через Linear API и в
репозиторий не выгружался); пин — URL + `updatedAt`.

Версии (строки FOR-4 взяты буквально): `observation_version = FOR-2-v0.2+errata-v0.2.1`,
`action_version = ActionV2`, `decoder_version = FOR-2-decoder-v0.2.1`.
Версии этого репозитория: `rules_version = l0-proto-FOR1-v0.2.1` (механика прототипа),
`balance_version = candidate-FOR1-v0.2.1-unvalidated` (числа до экономического пилота),
`serialization_version = formicmind-canonical-json-v1`, `rng_version = pcg32-xsh-rr-64-32-v1`.
`rules_version` и баланс разделены: смена кандидатных чисел не должна выдавать себя за смену механики.

## 2. Модель

* `SimConfig` (frozen): топология (7 узлов, 9 рёбер), `CandidateBalance`, K=30, T_max=3000.
* `SimState` (mutable, явный `clone()`): тик, еда узлов, две `ColonyState`, `next_unit_id`.
  Только состояние игровой модели. Политический RNG в нём **нет**.
* `ColonyState`: еда, `queen_hp`, `next_lay_tick`, `upkeep_remainder10`, `starvation_debt`,
  постоянные приказы, юниты, расплод, приватная `IntelMemory`.
* `RunState`: корневой seed и реестр именованных RNG-потоков (принадлежит runner, не миру).

Узлы: `0..6 = [A, N1, N2, C, N4, N5, B]` (канонический порядок FOR-2 для стороны A). Зеркало
стороны B: `MIRROR = (6, 4, 5, 3, 1, 2, 0)`.

Все игровые величины — целые: еда, HP, тики, ID; upkeep — в десятых (`4`/`8` на тик).

Стартовое состояние (`reset`) — ровно FOR-1 §3: еда 60, 12 рабочих (HP 20) + 4 солдата (HP 30)
дома, `queen_hp=240`, расплод пуст, `next_lay_tick=0`, остаток upkeep 0, долг голода 0;
запасы узлов N1/N2/C/N5/N4 = 60/40/80/40/60 (по таблице §3, регенерация и ёмкости из неё же).
Приказы при reset — из golden-фикстуры FOR-2 G0: `lay_order=none`, весь forage на `home`
(`forage_q=[65535,0,0,0,0,0]`), `garrison_home`, `avoid_center=false`.

### Выборы (не решения FOR-1/FOR-2)

1. **ID**: сторона A — рабочие 1–12, солдаты 13–16; сторона B — те же +16; `next_unit_id = 33`.
   ID яйца будет равен ID будущего взрослого (один аллокатор при кладке, без выделения при вылуплении).
2. **Группы не объекты**: хранятся записи юнитов `(unit_id, caste, hp)` с положением
   (узел либо ребро + `arrival_tick`) и целевым узлом; группы/агрегаты транзита — производные.
3. **«Нигде» = `-1`**: в каноническом формате нет `null`.
4. **IntelMemory после reset пустая** (`seen_tick=-1`, значения 0). Первую запись (собственный дом) делает
   сенсорная подфаза `PRE_POLICY(0)` в будущем PR agent-boundary. Память индексируется мировыми ID узлов.
5. **Приказы хранятся в системе координат стороны** (как в ActionV2): индексы forage/army — локальные,
   перевод в мировые узлы: `rules.local_to_world(side, local)`.
6. **Seed**: правила v0.2.1 случайность не потребляют, поэтому `SimState` от seed не зависит;
   `seed` задаёт корень реестра потоков (`RunState`). Оппонента выбирает harness (FOR-1 §7).
7. Топология (длины рёбер) — часть `rules`, числа узлов (запас, ёмкость, регенерация) — кандидатный баланс.
8. Constants боя (урон 2, множитель дома 5/4) и `starvation_unit_cost=5` лежат в `CandidateBalance`
   для полноты, хотя ни тик, ни бой здесь не реализованы.
9. `python >= 3.12` (`requires-python`) — версия, на которой запускались тесты.

## 3. RNG

PCG32 (XSH-RR, 64-bit state, odd increment), как в эталонном `pcg32_random_r` /
`pcg32_srandom_r`. Спецификация и формулы — в docstring `src/formicmind/rng.py`.

* `below(n)`: rejection sampling, `threshold = (2^32 − n) mod n`, без смещения.
* Поток называется **ролью**, не местом: `world`, `policy:<policy_id>:<replicate>`
  (`policy_stream_id`). Место A/B в идентификатор не входит, поэтому при парной смене мест
  политика получает тот же поток.
* Вывод seed потока: `SHA-256("formicmind/rng-stream/v1" ‖ 0x00 ‖ root_seed:u64be ‖ len(stream_id):u16be ‖ stream_id)`;
  `initstate = digest[0:8]`, `initseq = digest[8:16]` (big-endian). Python `hash()` не используется.
* Потоки создаются только явным `RunState.add_stream`, лениво — никогда.
* Known-answer тесты: эталонный вектор `pcg32 (42, 54)` из pcg-c demo (внешний референс) и
  регрессионные векторы вывода потока (внешнего референса у деривации нет).

## 4. Каноническая сериализация и хэши

* Типы: `int` (|x| ≤ 2^53−1), `str`, `bool`, `list`, `dict` со строковыми ключами. Без float, NaN,
  `null`, кортежей. Любые u64 (RNG state/inc, root seed) — **десятичные строки**
  (иначе Vue-читатель теряет точность выше 2^53).
* Байты: ключи отсортированы, разделители `,` и `:`, без пробелов, `ensure_ascii`, ASCII.
* Порядок массивов: узлы по `node_id`, колонии по стороне, юниты и расплод по `unit_id`,
  `forage_q` по категории, рёбра по `(a, b)`, ресурсы по `node_id`.
* Загрузка строгая: лишние/недостающие ключи, чужая схема, неотсортированные массивы,
  дубликаты ключей и неканонические байты — ошибка. После загрузки проверяются инварианты состояния.
* Хэши (SHA-256, hex, префикс домена + `0x00`):
  * `config_hash` — `formicmind/config/v1`;
  * `state_hash` — `formicmind/state/v1`: состояние правил (включая `next_unit_id` и хэш конфига), **без** RNG;
  * `checkpoint_hash` — `formicmind/checkpoint/v1`: `{state, run}`, то есть состояние + все RNG-потоки —
    всё, что нужно для продолжения прогона.
* Golden-хэши начального состояния лежат в `tests/test_serialization.py`. Это регрессионные значения,
  выданные реализацией; авторитетными они становятся после ревью PR.
