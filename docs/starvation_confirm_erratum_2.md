# FOR-35: erratum E2 к протоколу `formicmind.starvation-confirm/v1` — уточнения реализации и раскрытие пробного запуска

**Зарегистрирован:** 2026-11-03, после реализации и тестирования харнесса, **до** первого полного сравнительного прогона.
**К документам:** протокол (SHA-256 `445df9d9b499abee5124cbf467b10e0a82626d871129289c75041145265deeda`) и erratum E1 (SHA-256 `a8782cb3e099933032c5843661530b3b274abffa96718d961cfb7f82634e387b`). Ни протокол, ни E1 не редактируются. Erratum не меняет ни одного порога, определения вариантов, расписания, критерия K0–K7 и вердикта; он раскрывает один отступ от процедуры и фиксирует толкования формулировок, которые при реализации оказались неоднозначными.

## E2.1. Раскрытие: пробный запуск одной группы расписания

Протокол запрещает промежуточные просмотры результатов. При дымовой проверке харнесса **одна** из 960 групп расписания (`R0-T0`, `turtle:v2`–`raider:v2`, seed `20270501`, Turtle на A; пять вариантов и якорь A0) была выполнена, а краткие итоги выведены: причины терминала, число окон `stagnant` / `stagnant_deficit` / `stagnant_sat`, суммы `forgiven`, тик первого расхождения. Это не выбор по результатам: после просмотра **не** менялись варианты, пороги, определения метрик, расписание, критерии или набор анализов. Строки этой группы не сохранялись; они будут перегенерированы в полном прогоне, как и остальные. Дальнейшие тесты используют только seeds вне расписания (`20270301`, использован в FOR-25).

## E2.2. Толкования (не изменяют пороги и определения)

1. **Единицы времени.** Число завершённых тиков `n_c` равно `state.tick` на терминале (для таймаута 3000; для `queen_death` с обрывом тика — тик не завершён). Событие тика `t` относится к окну `k`, если `300k ≤ t < 300k+300`. «Состояние после `m` завершённых тиков» — состояние с `state.tick = m`. Для `new_peak` максимум `N` берётся по состояниям с `m ∈ (300k, 300k+300]`, а `P` — по всем состояниям с `m ≤ 300k` (включая `m = 0`). Стороны и места привязаны к политикам; `A` считает всех взрослых, включая в пути, `B` — весь расплод.
2. **Атрибуция прощения (раздел 7 протокола).** Суммы `Σforgiven` и `Σmissing` берутся по обеим колониям и по всем окнам `stagnant_deficit` строки: `2·Σforgiven ≥ Σmissing`.
3. **Строки экспозиции.** Строка A0 называется *строкой экспозиции*, если у неё ≥ 5 окон `stagnant_deficit` **и** выполнена атрибуция из п. 2. Кластер экспозиции — A0-кластер, содержащий хотя бы одну строку экспозиции (любой seed, любое место). Класс разрешения кластера (раздел 10 протокола) вычисляется только по строкам экспозиции кластера: для каждой такой строки A0 берётся строка варианта с тем же ключом (карта, пара, seed, место), класс строки определяется формулой раздела 10, класс кластера — худший по этим парам.
4. **`viable(V) ≥ ⌈E/2⌉`** проверяется только при `E > 0`; при `E = 0` K4 не выполняется ни у одного варианта, и вердикт определяется пунктом «A0 оставить».
5. **Индикатор `tl`.** Колония Turtle определяется по политике. `tl = 1`, если причина терминала `queen_death` или `economic_collapse` и мировая сторона Turtle входит в `sides` терминала (при `queen_death` это стороны с погибшей маткой, при коллапсе — стороны с коллапсом экономики).
6. **K7.** Для каждой строки варианта `V`, у которой в строке A0 с тем же ключом **ни у одной** колонии нет тиков недоплаты (`deficit_ticks = 0` у обеих), хеш нормализованной траектории обязан совпасть с A0. Любое несовпадение — нарушение целостности (вердикт «недостаточно данных»).
7. **Порядок вердикта.** Проверки раздела 10 выполняются в таком порядке: (K0 или K1 не выполнены) → число A0-кластеров `|𝒦| < 120` → `0 < E < 6` → `E ≥ 6`, но не выполнено распределение K2 → (`E = 0`) → «A0 оставить», если ни один вариант не проходит K3 ∧ K4 ∧ K5 ∧ K6 ∧ K7 → иначе «требуется новая `rules_version`». Правило покрытия (`|𝒦| < 120`) применяется до `E = 0`.
8. **Слабый вывод.** Вердикт «требуется новая `rules_version`» помечается слабым, если `E ∈ {6, 7}` или экспозиция лежит в единственной ячейке (карта, пара).
9. **Выбор кандидата** при нескольких прошедших: лексикографически минимум `(X(V), T_loss(V) − T_loss(A0), сложность)`, сложность `A1b < A2 < A3b` (`A1a` — последним; он не может пройти K3, если сохраняет прощение на M1).
10. **Первый тик расхождения.** Для строки варианта это первый тик, на котором хеш потока событий этого тика отличается от хеша A0-прогона того же расписания (`-1`, если нет); при разной длине прогонов — длина более короткого. Группа расписания выполняет пять вариантов одного (карта, пара, seed, место) подряд в одном процессе; это техническая единица исполнения, расписание строк не меняется.
11. **Описательные сверки с FOR-25 (c1–c4, раздел 9).** (c1) «воспроизведено», если `Σforgiven(A1a)` на M1 > 0. (c2) среди кластеров Turtle–Raider с таймаутом во всех строках A0 доля кластеров, где таймаут сохраняется при всех четырёх кандидатах, не меньше половины. (c3) `T_loss(V) ≥ T_loss(A0)` для всех четырёх кандидатов. (c4) `10·X(V) ≤ |𝒦_non|` для всех четырёх кандидатов. Тип застоя Turtle–Raider «зависит от правила», если устойчивая стагнация (≥ 5 окон `stagnant`) в кластере A0 исчезает хотя бы под одним кандидатом (в строках всех членов), иначе «не зависит».
12. **Верификация.** `verify` сверяет статическую часть манифеста целиком, хеши защищённых файлов только для файлов, перечисленных в манифесте (изменение или удаление — отказ; новые файлы не мешают), и побайтно все артефакты с полной регенерацией. Fingerprint пакета с харнессом в момент прогона хранится в манифесте и в проверку не входит (сообщается). Хеши артефактов считаются от байтов с нормализацией CRLF→LF.
13. **Предпрогонная проверка** (`preflight`): FOR-25 влит (предок HEAD — коммит `720e2d7cd3465afbc74e1fe7a1849f1c5b56f334`), коммит протокола — предок HEAD, SHA-256 протокола и всех erratum совпадают, fingerprint движка совпадает, отслеживаемое дерево чистое и нет неотслеживаемых файлов в `src`, `docs`, `tests`, `scripts` (неотслеживаемые файлы в `results` игнорируются: они вне схемы), `git rev-parse --show-toplevel` равен корню модуля (пакет импортируется из активного checkout), seeds не встречаются ни в одном отслеживаемом файле вне файлов этого исследования.
14. **Размер строк.** Окна и профили хранятся компактными списками фиксированного порядка (`side_window_fields`, `match_window_fields` в манифесте); дробные величины в артефактах хранятся парами `num`/`den` или как целые.

## E2.3. Процедура

Erratum коммитится отдельным коммитом после E1 и до первого полного прогона. Манифест фиксирует SHA-256 E1 и E2; `preflight` и `verify` отклоняют прогон при отличии.
